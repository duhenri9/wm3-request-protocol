# Princípios do WM3 Request Protocol

## 1. Contexto antes de solução

Um pedido sem contexto força quem executa a adivinhar.

## 2. Fonte de verdade antes de opinião

Toda mudança precisa dizer qual versão, decisão, tela, commit ou documento deve ser preservado.

## 3. Escopo pequeno vence escopo heroico

PR pequeno é mais fácil de revisar, testar e reverter.

## 4. Fora do escopo é proteção

Dizer o que não deve mudar evita regressão.

## 5. Critério de pronto precisa ser observável

"Melhorar" não é critério de pronto. "CTA visível no primeiro viewport mobile" é.

## 6. Gate não é burocracia

Gate existe para impedir que algo pareça pronto antes de estar pronto.

## 7. Mudança visual não deve virar mudança estratégica

Ajustar layout não autoriza trocar oferta, promessa ou preço.

## 8. Falso positivo é pior que falha clara

Um sistema que diz "sucesso" quando falhou cria perda de confiança.

## 9. IA precisa de fronteira

Agentes de código executam melhor quando o pedido define contexto, limite e validação.

## 10. Linha de controle

Toda requisição deve preservar a direção do projeto.
